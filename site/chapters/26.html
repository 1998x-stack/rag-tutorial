FRONTIER / METHODS

前沿 RAG 技术：
按“在哪一步动手”来分类

CRAG、Self-RAG、FLARE、Speculative RAG 常被列成一张“技术清单”，但它们不是互相替代的选项——它们是在流水线的不同位置动手。把它们按“改检索、改生成、加校验”归位，才知道自己缺的是哪一环、该不该付出那份延迟。

定位检索侧生成侧校验

MECHANISM / PROBLEM

前沿技术不是银弹

一个常见的误解是“把前沿技术堆上去，系统就会更好”。实际上，每一项前沿方法都是针对某一类失败的定向修补，并且都要付出延迟或复杂度。如果绝大多数查询是简单的单跳问答，这些机制不仅没有收益，还会把延迟和 token 消耗推高。而且瓶颈往往不在生成侧——很多时候先要解决的是分块与召回（见第四、五、六章）。

不引用未经测量的“提升 / 代价”百分比。原站页面里“召回率骤降到 40% 以下”“延迟 +200%~300%”“减少 30% 幻觉”“检测 80%+ 幻觉”等数字无可靠出处，本页已删除；下方的技术对比也不给具体百分比。这些值必须在自己的数据与模型上实测。

另一类误解是把它们当成“新一代标准流程”逐层叠上去。更合理的看法是按流水线的位置分类：它们分别在“检索取舍”“生成方式”“独立校验”三处动手。先诊断自己的瓶颈在哪一环，再去选对应位置的方法。

MECHANISM / CORRECTIVE

改检索取舍：CRAG 与 Self-RAG

这一类方法的共同点是：不把检索结果无条件地塞给模型，而是先评估再决定怎么用。

Corrective RAG（CRAG，Yan 等，2024）引入一个轻量的检索评估器，对取回的文档打分，再按分数走不同分支：质量高则保留高相关文档（过滤低相关）；质量一般则尝试用扩展查询再检索；质量差则回退到“不用外部资料”的生成（或直接拒答）。它把“检索可能错”变成了一条显式的处理分支。

Self-RAG（Asai 等，2023）把这种判断交给被训练过的模型本身：模型会输出“反思标记”，决定是否需要检索、以及生成的内容是否被检索结果支持。好处是决策与生成在同一个模型里，坏处是需要专门的训练数据与模型。

代价：多了一次评判。无论是外接评估器还是模型自带反思标记，都会增加一次模型调用或额外的生成开销。评估器本身也会有假阳 / 假阴（见第十五章的 NLI）。所以“加一个评估器”不能假定一定更好，除非在你的数据上实测过。
根据最高相关性分数，决定保留 / 扩展 / 回退。

MECHANISM / GENERATION

改生成方式：FLARE 与 Speculative RAG

这一类方法不动检索器本身，而是改变生成与检索如何交织。

FLARE（Jiang 等，2023）把“先检索、后生成”倒过来一部分：在生成过程中，如果即将生成的下一段内容置信度低，就用这段“即将出现的未来内容”组成查询去主动检索，再把新资料接回生成。它适合长文本问答与多跳问题，但会多次调用检索与生成，延迟明显上升。

Speculative RAG（Wang 等，2024）换个思路提高吞吐：用一个较小的草稿模型，对不同的检索子集分别写出多份候选草稿，再用一个较大的验证模型一次选出最好的那份。因为草稿可以并行生成，它把“多次采样”变成可并行的过程，验证模型只需跑一次。

它们不改变召回本身。FLARE 与 Speculative RAG 处理的是“怎么用已有的检索能力”，不能修复“库里根本没有相关资料”。如果问题在召回，先回到第五、六、七章。

MECHANISM / VERIFICATION

加独立校验：Self-Refine 与 CoVe

第三类方法在生成之后再加一道“检查—修正”：

  • Self-Refine（Madaan 等，2023）：模型先给出初稿，再对自己的输出提出反馈并修订，可迭代多轮。优点是无需额外训练；它依赖模型能否诚实地指出自己的错。
  • Chain-of-Verification（CoVe，Dhuliawala 等，2023）：先生成一组验证问题，再独立地回答这些问题（避免与初稿上下文共享偏差），最后据此修正答案。它把“自检”拆成可独立回答的子问题。

这一类与第十五章的幻觉检测同源：本质上都是外部 / 二次判断，可以用 NLI 模型、规则或另一个 LLM 来实现。多层校验可以叠加，但越叠越贵，且无法保证零漏网。

“自查”不是保证。让同一个模型检查自己，可能重复同一个错误（它“相信自己”）。高风险场景仍需外部证据（引用）或人工抽查。自我校验能降低错误率，但不能保证正确。

MECHANISM / DECISION

怎么选、怎么不踩坑

先诊断，再选方法。把失败现象映射到可能的位置：

现象先考虑的位置
召回了不相关的资料，却没被过滤检索取舍（CRAG 类评估器）
模型凭空补充了资料里没有的内容检索取舍（按需检索）+ 生成侧约束
长回答后面越写越偏生成方式（FLARE 类边生成边检索）
吞吐不够、想并行生成候选生成方式（Speculative 类草稿 + 验证）
回答大体对，但有零星事实错误独立校验（Self-Refine / CoVe / NLI）
库里根本没有相关资料都不适用：回到解析、分块与召回

几条避坑原则：

  • 先测基线，再加机制。没有对照就不知道新机制是否真的带来净收益（第十八章）。
  • 不要一次性堆叠全部。每加一层都要单独计量它带来的延迟与质量变化，否则无法归因。
  • 认清前提。这些方法都假定底层检索与生成基本可用；若召回本身就差，先修召回。
  • 当心延迟预算。多数方法会多次调用模型；对延迟敏感的在线系统，要用前置于查询分类的路由（第二十一、二十二章）。

来源与延伸阅读

  1. Yan et al., Corrective Retrieval Augmented Generation (CRAG, arXiv:2401.15884) — 检索质量评估与保留 / 扩展 / 回退分支
  2. Asai et al., Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection (arXiv:2310.11511) — 反思标记与按需检索
  3. Jiang et al., Active Retrieval Augmented Generation (FLARE, arXiv:2305.06983) — 生成过程中主动检索
  4. Wang et al., Speculative RAG: Enhancing Retrieval Augmented Generation through Drafting (arXiv:2407.08223) — 草稿模型与验证模型的两阶段生成
  5. Madaan et al., Self-Refine: Iterative Refinement with Self-Feedback (arXiv:2303.17651) — 自我反馈与迭代修改
  6. Dhuliawala et al., Chain-of-Verification Reduces Hallucination in Large Language Models (arXiv:2309.11495) — 先生成验证问题再逐条核对
