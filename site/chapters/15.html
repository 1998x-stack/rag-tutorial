MECHANISM / PROBLEM

引用对了，事实为何仍可能错？

上一章把“回答有没有引用来源”做了校验，但引用成立只是第一步。先区分两个容易被混为一谈的词：

  • 忠实性（faithfulness）：回答是否忠于给定的资料，没有资料之外的内容。
  • 事实性（factuality）：回答是否与真实世界一致。

RAG 能显著提高忠实性，因为答案被约束在检索到的段落上；但它不保证事实性。如果检索到的资料本身过时、残缺或相互矛盾，那么“忠实地依据资料”的回答仍可能与事实不符。反过来说，即使资料正确，模型也可能在资料允许的范围内“说过头”。所以“RAG 能消灭幻觉”是一个不成立的期待。

幻觉是一个概率现象，不是开关。检索增强降低的是“凭空编造”的概率，而不是把它归零。要做生产系统，需要的不是一句“已经解决”，而是一套能定位幻觉来源、并在生成后做核验的机制。这就是本章要做的事。

MECHANISM / TAXONOMY

幻觉从哪来：五类来源

把幻觉一概而论，就无法针对性处理。下面五类是工程中常见的归纳（属于教学分类，不是某个论文的官方划分），它们可以共存，也可能在一次回答里叠在一起。

来源表现为什么会发生检测难度
上下文冲突回答在多篇资料间选了一边检索到的资料本身相互矛盾中
上下文不完整丢掉了关键限定条件检索段落截掉了“但仅限……”等限定高
过度外推“合理”地补了资料里没有的细节模型倾向于把话补完整极高
事实漂移从正确开头逐渐走偏生成越长越容易累积偏离中
知识边界混淆用自己记忆覆盖了检索知识预训练知识与资料冲突时倒向自己高

幻觉的分类一般先区分“与真实世界不符”（factuality）与“与给定资料不符”（faithfulness），我们这里的五类更偏向后者。要检测它们，思路上分三条路线：用资料做“前提”做一致性检查（下一节）、把回答拆成原子声明逐条核验、以及在没有参考资料时靠多采样一致性兜底。

MECHANISM / NLI

NLI 一致性检查：把资料当“前提”

自然语言推理（NLI）是事实一致性检查的主力方法。它的输入是一对句子：前提（premise，这里是被引用的资料段落）与假设（hypothesis，这里是模型生成的声明）。NLI 模型输出三种关系的概率：蕴含（entailment，前提支持假设）、中立（neutral，前提不足以判定）、矛盾（contradiction，前提与假设冲突）。

y^=argmaxc∈{E,N,C}p(c∣premise,hypothesis)

其中 E/N/C 分别是蕴含、中立、矛盾。约定是：只有蕴含才算“被资料支持”；中立与矛盾都要被标记。下图展示这条判定链。

用 NLI 衡量事实一致性有成熟的工作：TRUE（Honovich 等，2022）系统比较了多种一致性指标，并强调 NLI 既能做参考式也能做无参考式评估；SummaC（Laban 等，2022）则指出现成 NLI 在长前提上会退化，需要先拆成句对再聚合。这提示了一个实用结论：不要把整段长文当成一个前提直接判，而要拆小粒度。

NLI 不是真理判决器。它有假阳（把相关当成支持）与假阴（把正确的改写判成中立）。长前提、复杂否定、数值表述都会让准确率下降，而且不同模型的判定并不一致。它给出的是一个可审计的近似信号，应与抽样人工审核一起用。

MECHANISM / PIPELINE

原子声明与分步验证

把整段回答当成一个整体去判“能不能被资料支持”，粒度太粗：一段话里可能一句对、一句错、一句无据，合在一起判就会把错误淹掉。更稳的做法是把它拆成原子声明（atomic claim）——每条只表达一个可验证的事实，再逐条核验。

这条“拆原子事实再逐条核验”的思路在 FActScore（Min 等，2023）里被形式化：把长文本分解为原子事实，分别验证，最后用被支持的事实占比作为事实精确度。实践中声明提取可以用规则（按标点/连接词切分）、也可以用一个专门的 prompt 或模型来做——下一节给出一个纯规则的玩具演示。

拆分本身也会出错。切得太碎会把一个完整事实拆成两个互相依赖的片段；切得太粗又会重新退化成“整段一起判”。声明提取的质量直接决定了后面核验的上限。

MECHANISM / SELF-CONSISTENCY

无参考时：多采样一致性

前面两种方法都靠“参考资料”做前提。但在纯生成场景里，可能根本没有可对照的上下文。SelfCheckGPT（Manakul 等，2023）提出了一个不靠外部知识的思路：如果模型对某个事实是“真知道”的，那么多次采样生成的描述应该彼此一致；如果某段内容属于幻觉，不同采样之间往往会互相矛盾。

做法是：对同一个提示进行 N 次采样（论文实验中常用 5～10 次），然后把每次采样里的句子与其他采样里的内容做一致性比较。常用的比较信号包括：

  • 语义相似度：用句向量或 BERTScore 类的指标衡量两次描述是否说的是同一件事。
  • 矛盾检测：用 NLI 看两句是否相抵。
  • 问答一致性：从一句生成问题，用另一句回答，看答案是否匹配。
一致不等于正确。模型可能稳定地把同一个错误重复很多遍（系统性错误），这时多采样反而“一致地错”。SelfCheckGPT 针对的是随机型幻觉，对系统性偏差无能为力。另外它的代价不小：需要生成 N 次，还要做互相比较，延迟与成本远高于单次生成。

MECHANISM / EXPERIMENT

纯 Python 演示：声明拆分

声明级核验的第一步是把回答拆小。下例用一个纯规则的切分（在句末标点或并列连接词处断开）把一段回答拆成原子声明。它不是真正的语义拆分，只用于说明“拆小再核验”这个流程。

# 声明拆分：只用标准库的规则切分，不用模型
import re

answer = ("Transformer 的 self-attention 可以并行计算，且通过位置编码感知顺序。"
          "它的复杂度随序列长度平方增长。")

# 在句末标点或并列连接词处切分
parts = re.split(r"[。；;]|，且|，并|，以及", answer)
claims = [p.strip() for p in parts if p.strip()]

for i, c in enumerate(claims, 1):
    print(f"声明{i}: {c}")
# 预期输出：
# 声明1: Transformer 的 self-attention 可以并行计算
# 声明2: 通过位置编码感知顺序
# 声明3: 它的复杂度随序列长度平方增长

运行条件：Python 3.10+，无第三方依赖、无网络。它拆出的每条声明仍需另外的NLI 或 LLM 判定才知道是否被支持；规则拆分也无法处理指代、省略与嵌套从句。把它当成上图的“拆分”小环节即可。

MECHANISM / FAILURES

失败边界与阈值权衡

任何幻觉检测器都会往两个方向犯错：漏检（把含幻觉的回答判为可信，风险上升）与误拒（把正确回答判为不可信，可用性下降）。调高判定阈值会让检测器更保守，漏检变少，但同时误拒变多。两条曲线总是往相反方向走。

不同检测手段在成本、延迟与覆盖面上差异很大，下面的对比只给定性取向（不引用任何具体毫秒数，因为延迟强依赖于模型、硬件与实现）：

手段原理相对代价擅长
提示约束要求只依据资料、强制引用几乎为零降低“自由发挥”，但不能事后发现错误
NLI 后验检测生成后拿资料做一致性判定低（一次 NLI 推理）粗粒度过滤
声明分解验证拆原子声明逐条核验中（多次判定）定位到具体哪句错了
多采样一致性多次生成看是否一致高（多次生成）无参考场景的随机型幻觉
外部工具核验调用搜索/数据库二次验证高（外部调用）可核验的硬事实，但覆盖面受限
不要把阈值一刀切，也不要把“拒绝率”忘了。同一阈值在医疗与闲聊里含义完全不同。评估时至少同时看三项：漏检率、误拒率（拒绝率/可用率）与延迟——只看“拦住多少幻觉”会鼓励检测器把所有回答都拒掉。要下结论，应在带标注的幻觉数据集上测，RAGTruth（Niu 等，2024）就是面向 RAG 的此类语料之一。本页不引用任何具体百分比数字。

检测出幻觉之后，除了拒绝回答，还需要在输入与输出两端拦住不安全内容。如何构建多层防线，是下一章内容安全护栏的主题。
