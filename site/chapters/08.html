RETRIEVAL / SPARSE

稀疏检索：
倒排索引与 BM25 的词频饱和

稠密检索按“意思相近”找证据，却常在型号、编号、专有名词上翻车。这一篇解释为什么基于词项的稀疏检索至今不可替代，BM25 又比朴素的词频打分改进了哪里。

精确匹配的需求倒排索引BM25 公式纯 Python 实现

MECHANISM / PROBLEM

为什么型号、编号总被检索错？

假设知识库里有多个型号的电机手册：“X-200 额定功率 2.2 kW”“X-210 额定功率 3.0 kW”。用户问“X-200 的额定功率是多少”。稠密检索把文本编码成语义向量，而“X-200”与“X-210”在语义上几乎无处不同——它们都是“某型号电机”的向量邻居。于是向量检索可能把 X-210 的手册排在 X-200 前面，给出的数字看似合理却是错的。

型号、版本号、错误码、法条编号、专有名词都属于同一类：区分它们的信息在具体字面上，而不在“意思”里。这正是基于词项（term）的稀疏检索的战场：它只关心文档里是否出现了这个词项，以及出现了几次，不把“相似”抽象成语义距离。

两种检索不是替代关系。稀疏检索善于精确字面命中，对同义改写、跨语言、无共享词的语义匹配很弱；稠密检索恰好相反。现代系统常把两者并行召回后融合，但理解 BM25 的机制是设计融合与调参的前提。

MECHANISM / STRUCTURE

倒排索引：以词为中心的查表

正排索引以文档为中心：每篇文档记录了它包含哪些词。如果要查找“苹果”，就得逐篇扫描。倒排索引反过来，以词为中心：为每个词维护一张列表，记录它出现在哪些文档中、出现几次。查找时直接定位到该词的列表，无需扫描全库。

列表中的每一项通常包含文档 ID 与词频（term frequency，tf）。把多个词项的列表做交集或并集，就可以回答“同时包含 A 和 B”这类查询。这就是搜索引擎能在毫秒级返回结果的底层结构，也是 BM25 评分的输入。

MECHANISM / MOTIVATION

从 TF-IDF 到 BM25 的两个修正

有了倒排索引，还需要给每个“文档—词项”对打分。最基础的方案是 TF-IDF：词频 tf 越高越重要，逆文档频率 idf 衡量词项稀罕程度——包含该词的文档越少，区分力越强。IDF 的一种常见形式是 idf = log(1 + (N − n + 0.5)/(n + 0.5))，其中 N 是文档总数、n 是包含该词项的文档数。

直接用 tf 乘以 idf 有两个缺陷，BM25 分别做了修正：

缺陷一：词频无上界

同一词从出现 1 次到 20 次，tf 线性增长，导致反复堆砌关键词的文档得分异常高。BM25 让词频贡献饱和：多十次的边际收益远小于多一次，由参数 k1 控制。

缺陷二：长文档天然占优

长文档词项多、频率高，即使内容不相关也可能得分高。BM25 按文档长度做归一化，用参数 b 控制在多大程度上抵消长度差异。

这两个修正让 BM25（Best Matching 25，来自概率检索模型）成为长期被广泛使用的词项检索基线：它不必训练、可解释、对精确词项敏感，且在多数标注集上仍是强基线。

MECHANISM / EQUATION

BM25 评分公式

给定查询 Q 与文档 D，BM25 把查询拆成词项 qi，对每个出现在文档中的词项打分后求和：

Score(Q,D)=∑qiidf(qi)·tfi(k1+1)tfi+k1(1−b+b·|D|avgdl)

其中 tfi 是词项 qi 在文档中的出现次数，|D| 是文档长度（词项数），avgdl 是集合中文档的平均长度，k1 与 b 是两个非负参数。分子里的 (k1+1) 是一个归一化常数，使不同 k1 的分数量级可比；真正控制形状的是分母。

实现差异。不同库对 IDF 的具体形式与平滑、对“文档长度”是否计重复词、是否加文档长度下界等细节不一致。因此“BM25 得分 12.3”只在同一实现、同一分词、同一语料内可比，不能拿去和另一个库的得分比较。

MECHANISM / PARAMETERS

k1 与 b：词频饱和与长度归一化

k1 控制词频的饱和速度。当 k1=0 时分式退化为 (tf·1)/tf = 1，词频几乎失去作用，得分只由 IDF 决定；k1 越大，词频增长的边际影响越明显。直观上，分数随 tf 单调上升但趋近上界——重复更多次带来的增量越来越小。

b 控制文档长度归一化的强度，取值在 0 到 1 之间。b=0 时完全不看长度；b=1 时完全按长度归一化。下图展示分母中的长度因子如何随 |D|/avgdl 变化：文档越长，分母越大，词频被压得越低。

关于默认值：Lucene 与 Elasticsearch 的 BM25 实现默认 k1=1.2、b=0.75，这被很多系统沿用；但“1.2/0.75”是实现默认值，不是普适最优值。短文本（标题、查询）通常适合更小的 k1，长度差异大的集合适合更大的 b。正确做法是在自己的标注查询集上用网格搜索或贝叶斯优化调参，而不是照搬常数。

MECHANISM / ENGINEERING

中文分词与词典的现实取舍

BM25 的输入是一串词项，但“词”并不天然存在。英文可以按空白切分再配合词干化与停用词，而中文没有空格：分词结果直接决定倒排索引里有哪些词项，也就直接决定 df 与 IDF。

如果领域术语被切碎，检索就会出事。例如“心肌梗死”若被切成“心肌”与“梗死”，那与“心肌炎”的区分度会下降，作为完整短语的 IDF 也无法体现。常见做法有三类：

分词策略优点代价
第三方分词 + 领域词典（如 jieba 自定义词典）词粒度贴近语义，命中率好引入依赖；词典要维护，新词需更新
字符二元组（bigram）无词典、无依赖、对未知词鲁棒词项数膨胀；索引与查询都更“噪”
按字切分（unigram）最简单区分度差，常见字噪声大

三种都可用于 BM25，但得分不可直接对比，因为词项空间不同。关键工程点：索引与查询必须使用完全相同的分词器、词典与版本；换分词器等于换了一套词项，必须重建索引，并重新调 k1、b。

MECHANISM / EXPERIMENT

纯 Python 实现与不变量

下例用标准库实现 BM25。为了不引入分词依赖，中文用字符二元组作为词项——这只是可复现的教学分词，不等于生产级分词。它要验证的不变量是：同一词项在文档中越频繁，tf 贡献单调上升但趋近上界。

import math, re
from collections import Counter

def tokenize(text):
    text = text.lower()
    latin = re.findall(r"[a-z0-9]+", text)
    han = re.findall(r"[\u4e00-\u9fff]", text)
    bigrams = [han[i] + han[i+1] for i in range(len(han) - 1)]
    return latin + bigrams

docs = [
    "2026 版退款政策：付款后 7 天内可申请退款。",
    "2025 版退款政策：付款后 3 天内可申请退款。",
    "2026 版账户安全：建议开启二次验证。",
]
tok = [tokenize(d) for d in docs]
N = len(docs)
avgdl = sum(len(t) for t in tok) / N
df = Counter()
for t in tok:
    df.update(set(t))
idf = {w: math.log(1 + (N - n + 0.5) / (n + 0.5)) for w, n in df.items()}

def bm25(query, k1=1.2, b=0.75):
    q = tokenize(query)
    out = []
    for i, t in enumerate(tok):
        tf, s = Counter(t), 0.0
        for w in q:
            f = tf.get(w, 0)
            if w not in idf or f == 0:
                continue
            s += idf[w] * f * (k1 + 1) / (f + k1 * (1 - b + b * len(t) / avgdl))
        out.append((i, round(s, 4)))
    return sorted(out, key=lambda x: -x[1])

print(bm25("2026 退款"))
# 实测输出：[(0, 1.0919), (1, 0.6344), (2, 0.4971)]，即 文档 0 > 文档 1 > 文档 2。

上面那行注释是真实运行结果：文档 0（1.0919）同时命中“2026”与“退款”（“退款”出现 2 次），排名最高；文档 1（0.6344）虽标着 2025 版，却同样把“退款”写了 2 次，因此高于只命中一次“2026”的文档 2（0.4971）。可见排序由命中的词项、词频与文档长度共同决定，版本号本身并不直接加分。运行条件：Python 3.10+，无第三方依赖、无网络。注意三个边界：不同分词器会得到不同词项空间，得分不可互相比较；IDF 的具体形式因实现而异；“二元组分词”会把长句切出大量重叠片段，召回高但噪声也大。它演示的是机制，不是一套可直接上线的检索配置。

BM25 的 tf 贡献随出现次数上升但趋近上界 k1+1；k1 越大，上界越高、饱和越晚。

MECHANISM / ACCEPTANCE

与稠密检索的分工和失败边界

BM25 与稠密检索的能力互补，可以用一张表概括分工：

查询类型BM25 / 稀疏稠密向量
型号、编号、错误码直接命中字面词项易被“相似的其它编号”干扰
同义改写、口语提问无共享词时召不回语义相近即可召回
新词、专有名词无需训练，只要入库就有词项取决于嵌入模型是否见过该词
可解释性能给出命中的词项及权重距离分数较难解释

因此现代系统常采用混合检索：两路并行召回后按排名融合，再用重排序模型精排。但“混合一定更好”不是普遍规律，需在自有标注集上验证。

失败边界。（1）BM25 不处理语义：查“感冒”找不到写“上呼吸道感染”的文档，需靠查询扩展或稠密检索补。（2）分词错误直接转化为漏检。（3）跨库得分不可比，融合前通常要先把两路分数归一化到同一尺度。（4）参数默认值不是最优值，必须在自己的数据上调参并报告设置。
