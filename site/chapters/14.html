GENERATION / ATTRIBUTION

生成与引用溯源：
让回答有据可查

检索与重排都对了，回答却仍可能掺进资料之外的内容，或把来源标错。这一篇解释生成阶段怎样把随机性调低、提示怎样封住“自由发挥”的出口、引用怎样从资料一路标到用户，以及生成之后如何用编号校验与归因核查兜底。

降低随机性约束提示内联引用归因核查

MECHANISM / PROBLEM

拼上资料，为什么答案还不可信？

一个常见的误解是：只要把检索到的文档拼进提示，回答就自然“有据可查”。实际上这是两个彼此不同、必须分别检查的问题：

  • 忠实性（faithfulness）：回答里的每个事实，是否真的被提供的资料支持？
  • 引用正确性（citation correctness）：回答标注的来源编号，是否真的指向支持该事实的那段资料？

这两件事会分别出错。模型可能说出资料里没有、但它自己“知道”的内容（忠实性失败）；也可能内容确实来自资料，却标错了编号或干脆不标（引用失败）。更麻烦的是，这两种失败的回答读起来往往都很通顺，仅凭肉眼很难发现。

“有据可查”是一个可检验的动作，不是一个感觉。要让它成立，必须在生成前后各加一道约束：生成时限制模型只能依据资料作答并标注来源，生成后校验这些来源是否合法、是否真的支持那句话。接下来的小节逐层展开。

MECHANISM / SAMPLING

生成参数：把随机性调低

语言模型不是“选定”下一个词，而是先给词表上每个词一个分数（logits），再用 softmax 把它变成概率分布，最后从这个分布里采样。温度 T 就是插在 softmax 里的一个缩放因子：

pi=exp(zi/T)∑jexp(zj/T)

其中 z_i 是第 i 个词的 logit，T > 0 是温度，分母对词表里所有词求归一化（也可以只看 top-k 或 top-p 保留的候选）。T 越小，分布越尖：高分词的概率被放大，采样结果更确定；T 越大，分布越平：低分词也有机会被选中，输出更多样、也更不可控。

MECHANISM / KNOBS

常调的几个旋钮

除了温度，还有几个常用参数。下表是工程惯例与取向，不是硬性数值：具体取值依模型与任务而异，应看评估结果而不是照抄。

参数作用RAG 场景常见取向调节影响
temperature缩放 logits，控制分布尖锐度偏低（更确定）高→更随机、更易偏离资料；低→更稳定
top_p只保留累积概率达 p 的最小候选集偏低（筛掉长尾）高→候选变多；低→更确定
top_k只保留概率最高的 k 个候选小 k 以聚焦k 大→多样；k 小→保守
max_tokens回答长度上限按任务设上限太短→不完整；太长→易跑题
frequency_penalty / presence_penalty降低重复词 / 鼓励新内容通常不调或很小调高→降低重复，但可能伤及准确性
“把它们调到 0.1 就好”不是普遍规律。低温度能减少随机性，但不等于消除幻觉：即使贪婪解码，模型也会稳定地输出错误内容。这些数值是工程起点而非论文结论，换模型、换任务都要重新评估。真正降低幻觉还得靠提示约束与生成后校验。

MECHANISM / PROMPT

提示约束：不许“自由发挥”

检索增强生成的原始想法，就是让模型基于检索到的段落而不是仅凭参数记忆来作答（Lewis 等，2020）。但在提示里只写“请参考以下资料”远远不够——模型仍可能用自己的知识“补充”。要封住这个出口，提示需要同时交代四件事：

① 角色

告诉它“你是谁、在做什么”，例如“知识库问答助手”。

② 资料边界

明确“只能依据下面的资料”，不给“知道就直接回答”的出口。

③ 引用要求

规定每个事实后用编号标出来源，且不得编造编号。

④ 拒答出口

资料不足时明确说“根据提供的资料无法回答”，而不是硬编。

一个包含这四条要素的模板示例：

你是知识库问答助手。只能依据下面提供的资料回答，不得使用资料之外的知识。

【资料】
[1] 内容：……
    来源：文件标题 / 页码 / 日期
[2] …

【问题】……

【要求】
- 每个事实后用 [编号] 标注来源，如 [1]。
- 资料不足以回答时，明确说“根据提供的资料无法回答”。
- 不得编造资料中没有的数字、名称、来源编号。

【回答】
这是示意文本，不保证消除幻觉。不同模型对指令的遵从程度不同，同一模板换模型也可能变差。提示约束能降低“用自己知识”的倾向，但无法从机制上阻止误引或错误缩写；因此还需要下一步的生成后校验。要改模板，应拿评估集对照，而不是只凭肉眼。

MECHANISM / CITATION

引用机制：编号与结构化来源

引用是让“有据可查”从感觉变成可检查动作的接口：把回答里的事实与具体资料之间建立显式对应。两种常见形式是内联编号（回答里写 [1]、[2]）和结构化输出（把 answer 与 citations 分字段返回）。它们不是互斥的，可以同时使用。

形式例子优势局限
内联编号“…可并行计算 [1]”读者一眼看到出处，可点击跳转需解析文本才能自动校验
结构化输出{"answer":…, "citations":[…]}字段清楚，便于程序校验与前端渲染模型须可靠遵循 JSON 格式

结构化输出还能顺带带上置信度、可回链的段落位置等字段。但无论哪种形式，引用的正确性都必须校验：模型完全可能写出格式漂亮却指向错误段落的标注。

MECHANISM / VERIFICATION

生成后校验：编号与归因

提示约束能降低、但无法从机制上消除误引，所以要在生成之后再加一层机械校验。它分成两个粒度不同的级别：

  • 引用编号校验（句法级）：扫描回答里的每个 [n]，检查是否都落在 1 ≤ n ≤ N 内（N 是拼入提示的资料数）；越界或该标未标都算失败。便宜、确定、不需要额外模型。
  • 归因核查（语义级）：把回答拆成一条条原子声明，对每条声明用它亲自引用的那段资料做“蕴含判断”，看资料是否真的支持这句话。

归因核查通常借用一个自然语言推理（NLI）模型：输入是「声明 + 被引用的资料」，输出三选一——蕴含（资料支持声明）、中立（资料不足以判定）、矛盾（资料与声明冲突）。只有“蕴含”才算支持，后两者都要被标记。

这条“声明级归因”思路在多个工作中被具体化：Gao 等 2023 年的 ALCE 让模型生成带引用的文本并自动评估引用质量；Rashkin 等 2021 年的 AIS 用 NLI 把生成内容与来源做归因判断；Self-RAG（Asai 等，2023）则让模型在生成中自己输出“是否被支持”的标记。它们的共同点是：把“引用对不对”变成一个可计算的判断，而不是靠人工阅读。

归因核查也有假阳/假阴。NLI 模型本身会出错：把“相关但不支持”判成支持，或对复杂句过度严格。它指不了一个模型是否真的忠实，只能给出一个可审计的近似信号。因此它应与抽样人工审核、以及端到端评估一起用。

MECHANISM / EXPERIMENT

纯 Python 演示：引用编号校验

下面这段只做句法级校验：把回答里的 [n] 抽出来，检查是否落在 1..N 内。它不需要任何模型或网络，却能以极低成本拦住“引用了不存在的来源”这类错误。

# 引用编号校验：只用标准库，不用模型
import re

N = 3  # 拼入提示的资料条数
answer = "可并行计算[1]。位置编码提供顺序信息[2]。速度快了 5 倍[5]。"

cited = [int(n) for n in re.findall(r"\[(\d+)\]", answer)]
valid = [n for n in cited if 1 <= n <= N]
invalid = [n for n in cited if not (1 <= n <= N)]

print("出现编号:", cited)
print("合法:", valid)
print("越界:", invalid)
# 预期输出：
# 出现编号: [1, 2, 5]
# 合法: [1, 2]
# 越界: [5]

运行条件：Python 3.10+，无第三方依赖、无网络。它能证明的只是“这段回答里有一个越界编号”，不能证明内容是否真被资料支持。语义级的归因核查需要额外模型（见上一节），且本身也会出错。

同一条回答里的多个 [n]，校验器会分出合法与越界的编号。

MECHANISM / FAILURES

失败边界与评估

生成与引用阶段的失败，大多能归到少数几类。区分它们很重要，因为不同失败需要不同的检查手段。

失败模式表现应对方向
用自己知识补充回答含资料里没有的内容提示边界 + 声明级归因核查
来源编号越界标了 [5] 但只给了 3 篇资料生成后编号校验（句法级）
错引 / 误归因编号合法，但那段资料并不支持该句对它引用的资料做 NLI 归因
照搬原文大段复制、未做整合要求用自己的话重述，并做压缩
信息遗漏只用了一部分资料，忽略其余提示要求综合全部资料 + 提升重排精度
过度生成回答远超用户问的范围设 max_tokens + 要求简洁
置信度失真语气自信却内容有错拆声明核查；不确定时如实展示不确信
评估要量“引用对不对”，而不是“读起来像不像”。引用质量通常用引用精度/召回（标注的引用有多少成立、应标的地方有多少标了）与忠实性来衡量，且必须在同一标注集上对照。ALCE 这类工作提供的就是这样的自动评估框架。本页不引用任何“提升百分之几”的具体数字；要下结论，请在自己的数据上跑对照实验。

到这里，“检索 → 上下文 → 生成 → 引用”的生成主线已经完整。但引用正确不等于事实为真：资料本身可能过时，模型也可能在资料支持下“说得过头”。如何系统地检测幻觉、做事实核查，是下一章幻学检测与事实核查的主题。
